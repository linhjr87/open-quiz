# MLN131 Quiz Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the downloaded MLN131 FE exam images into a static GitHub Pages quiz site with one quiz per exam code, in two modes: Thi thử (mock exam) and Ôn tập (practice).

**Architecture:** There are two halves that share one JSON schema. (1) A data pipeline: Claude subagents transcribe the images in pass 1, then verify and solve them in pass 2. Small stdlib-only Python tools validate the data, build the manifest and merge comment answers. (2) A no-build static site: `index.html` and `quiz.html` are plain ES modules that read `data/*.json`. All pure logic lives in `assets/core.js`, which is unit-tested with `node --test`.

**Tech Stack:** HTML/CSS/vanilla JS (ES modules), Node 24 built-in test runner (tests only, not shipped), Python 3.12 stdlib + `unittest` (no pip dependencies), git.

**Spec:** `docs/superpowers/specs/2026-11-22-mln131-quiz-design.md`

## Review Focus

1. **Opening `quiz.html` with a bad or missing `?exam=` id**: the page should show "Không tìm thấy đề" with a link home instead of a blank page. Test: Task 5 `resolveExamId` cases, plus the manual check in Task 6.
2. **localStorage blocked or holding stale or corrupt data** (private mode, or an exam re-OCR'd so a saved answer points at an option that no longer exists): the quiz must still load and ignore the bad state. Test: Task 5 `loadState` / `sanitizeResponses`.
3. **Submitting a mock exam with unanswered questions, and the timer reaching 0**: unanswered questions count as wrong, and the timer auto-submits exactly once. Test: Task 5 `scoreExam` with blanks, plus the manual check in Task 6.
4. **Tied comment votes** (for example A:2, D:2): if the AI answer is among the tied top choices, the status is `verified`, otherwise `disputed`. Test: Task 2 `test_tie`.
5. **Long option text on a phone at 360px width**: the options wrap, nothing scrolls horizontally, and the tap target is the whole option row. Test: manual check in Task 6 at 360px width.

### Task 2: Manifest builder + comment-merge logic

**Files:**
- Create: `tools/build_manifest.py`, `tools/merge_comments.py`, `tools/test_tools.py`

**Interfaces:**
- Consumes: exam JSON schema (spec §5.3).
- Produces: `build_manifest(data_dir: Path) -> dict`, which returns `{"exams":[{id,title,term,code,count,stats:{verified,disputed,aiOnly}}]}` sorted by term (chronological SP<SU<FA within a year: order key `(yy, {"SP":0,"SU":1,"FA":2}[season])`, newest first) then code; skips `index.json`. CLI writes `data/index.json` (UTF-8, `ensure_ascii=False`, indent 2).
- Comment data source (produced by the user's other tool `fuexam_answers.py`, not by this repo): `D:/WORK/DEV/Tools/FU-Overflow/MLN131/answers_all.csv`, UTF-8 with BOM. The columns are `de,cau,dap_an,phieu,tong,dong_thuan,phan_bo,co`:
  - `de` is `<TERM>/<CODE>`, e.g. `FA24/B5-FE`.
  - `cau` is the question number = image number.
  - `phan_bo` is the vote distribution as a string, e.g. `A:3, D:1` or `AC:2, A:1`, or empty. Keys are sorted letter strings and may be multi-letter.

  The thread URL comes from `MLN131/<TERM>/<CODE>/comments.json` → top-level `"url"` (a path; prefix `https://fuexam.me`).
- Produces: `parse_dist(s: str) -> dict[str, int]`, which turns `"AC:2, A:1"` into `{"AC": 2, "A": 1}`. An empty or whitespace string gives `{}`.
- Produces: `reconcile(ai: list[str], votes: dict[str,int] | None, options: list[str], pick: int) -> tuple[str, list[str] | None]`, which returns `(status, commentAnswer)`. The rule:
  1. Drop vote keys whose length ≠ `pick` or that contain letters not in `options`.
  2. No votes left → `("ai-only", None)`.
  3. Otherwise `aikey = "".join(sorted(ai))` and `top` = the keys with the max count.
     - If `aikey in top` → `("verified", list(aikey))`.
     - Else → `("disputed", list(sorted(top)[0]))`.

  `answer` always stays equal to `aiAnswer`.
- Produces: `merge(exam: dict, dist_by_n: dict[int, dict[str,int]], source: str | None) -> dict`. For each question it sets `commentVotes` (the filtered votes dict, or null), `commentAnswer` and `status`. It sets `exam["source"]` when `source` is given.
- CLI: `python -I tools/merge_comments.py --csv <answers_all.csv> --mln <MLN131 dir> [--only FA24-B5-FE]`. For every `data/<id>.json` whose `<TERM>/<CODE>` appears in the CSV, it merges and rewrites the file (UTF-8, `ensure_ascii=False`, indent 2), then rebuilds the manifest. It prints `<id>: verified X, disputed Y, ai-only Z` per exam.

### Task 5: Core quiz logic (`assets/core.js`)

**Files:**
- Create: `assets/core.js`, `tests/core.test.mjs`, `package.json` (`{"type":"module","scripts":{"test":"node --test tests/"}}`, no dependencies)

**Interfaces:**
- Produces (all named exports):
  - `resolveExamId(search: string, manifest: {exams:{id}[]}) -> string | null`
  - `isCorrect(q, picked: string[]) -> boolean`: set equality with `q.answer`
  - `scoreExam(questions, responses: Record<number,string[]>) -> {correct, total, score10, wrong: number[]}`. `score10` is rounded to 2 decimals. Unanswered counts as wrong.
  - `sanitizeResponses(questions, raw: unknown) -> Record<number,string[]>`: drops unknown `n`, letters not in `options`, and non-arrays
  - `loadState(key: string, fallback) / saveState(key: string, value) -> void`: JSON in localStorage, try/catch, returns `fallback` on any error
  - `formatTime(sec: number) -> "MM:SS"` (clamps negatives to `00:00`)
  - `shuffled(arr, seed: number) -> array`: deterministic (mulberry32), does not mutate the input
  - `storageKey(examId, mode) -> "mln131:<examId>:<mode>"`
